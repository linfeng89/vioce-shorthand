### Sprint 2：离线转写 + 重试机制（3 天）

**状态**：⏳ 待开始

**前置依赖**：Sprint 1（录音服务）

**计划日期**：2026-05-05 ~ 2026-05-07

**开发内容**：

| 任务 | 优先级 | 预计工时 | 说明 |
|------|--------|----------|------|
| 集成 sherpa-onnx NuGet 包 | P0 | 2h | 添加依赖 |
| Whisper base 中文模型下载 | P0 | 1h | ~80MB 模型文件 |
| 实现 WhisperRecognizer | P0 | 4h | sherpa-onnx 调用封装 |
| 模型预加载（后台线程） | P0 | 2h | App 启动加载，不阻塞 UI |
| 转写队列实现 | P0 | 3h | FIFO 队列，动态重建 |
| 转写重试机制 | P0 | 2h | 最多 3 次，记录错误信息 |
| 手动重新转写功能 | P1 | 1h | 用户触发 |
| 转写中 UI 状态 | P1 | 2h | "转写中..."提示 |

**技术要点**：

1. **模型加载时机**：
   ```
   App 启动 → 后台线程加载模型（1-2 秒）
     → 模型就绪 → 转写队列可工作
     → 首次录音如未就绪 → 排队等待，录音不受影响
   ```

2. **转写队列恢复**：
   ```
   App 重启 → 查询 IsTranscribed=false 条目
     → 按 CreatedAt 排序 → 重新入队
     → 依次执行转写
   ```

3. **重试逻辑**：
   ```csharp
   try {
       text = await RecognizeAsync(audioPath);
       entry.TranscribedText = text;
       entry.IsTranscribed = true;
   } catch (Exception ex) {
       entry.TranscribeAttempts++;
       entry.TranscribeError = ex.Message;
       if (entry.TranscribeAttempts < 3) {
           // 下次空闲时重试
       } else {
           // 标记错误，用户可手动触发
       }
   }
   ```

**验收标准**：

- [ ] 录完音自动开始转写
- [ ] 中文识别准确率 > 85%（安静环境）
- [ ] 1 分钟音频转写时间 < 30 秒（中端机型）
- [ ] 转写失败可自动重试（最多 3 次）
- [ ] 用户可以手动触发重新转写
- [ ] App 重启后未转写条目自动恢复

**风险**：

| 风险 | 影响 | 应对 |
|------|------|------|
| sherpa-onnx 包体积大 | 安装包 +80~150MB | 可接受，base 模型中文效果好 |
| 推理速度慢 | 用户体验差 | 异步转写 + 通知，用户无需等待 |
| 方言识别差 | 用户投诉 | 提供手动编辑 + 保留原音频兜底 |

## 三、开发规范

### Git 分支策略

```
main (生产分支)
  └── 260502-chore-setup-voice-diary-framework
      └── 260502-feat-xxx（功能分支）
```

**分支命名**：`YYMMDD-(feat|fix|chore|refactor)-feature-name`

**示例**：
- `260508-feat-diary-list-page`
- `260509-fix-transcription-queue`
- `260510-chore-update-dependencies`

### 提交规范

```
<type>(<scope>): <subject>

<body>

<footer>
```

**Type**：
- `feat`: 新功能
- `fix`: Bug 修复
- `chore`: 杂项（配置、文档等）
- `refactor`: 代码重构

**示例**：
```
feat(recording): 实现录音手势识别

- 添加 PanGestureRecognizer
- 实现上滑锁定逻辑
- 添加上滑取消区域判断

Closes #12
```

### 代码审查清单

- [ ] 代码是否符合项目风格
- [ ] 是否有重复代码（DRY）
- [ ] 命名是否清晰准确
- [ ] 是否有必要的注释
- [ ] 是否考虑边界情况
- [ ] 错误处理是否完善

- [ ] 是否需要单元测试
